# Приём заявок с сайта

Все формы сайта (запись, перезвон, снимок, All-on-4, окно «Три врача», номер в подвале, страница записи) отправляют заявку в `lead.php` на том же хостинге. Приёмник:

1. проверяет номер, отметку согласия, ловушку для ботов, частоту заявок с одного IP и повтор той же заявки за 2 минуты;
2. записывает заявку в журнал на сервере в России (`data/leads`, ч. 5 ст. 18 152-ФЗ) и сразу отвечает посетителю;
3. создаёт сделку в amoCRM (воронка 7066886): контакт с телефоном (если номер уже есть в amoCRM, сделка встаёт к старому контакту), теги «Сайт» и название формы, UTM в поля «Статистика», примечание со всем, что человек указал, страницей, источником и отметкой о согласии;
4. по желанию пишет в Telegram-группу администраторов с кнопкой «Открыть сделку в amoCRM» (Ilya 22.10.2026: Telegram не используем, канал выключен);
5. добавляет строку в Google Таблицу;
6. по желанию клиники шлёт письмо на почту (выключено, пока в `config.php` пустой `mail.to`).

Если amoCRM, Telegram, таблица или почта не ответили, заявка остаётся в журнале и повторяется кроном (до 30 раз за 3 дня). В Telegram сразу приходит тревога «в amoCRM не попала», а после удачного повтора ссылка на сделку. Снимок из формы хранится на сервере, в примечании amoCRM ссылка на него с подписью.

Без PHP (демо на GitHub Pages) формы только показывают «спасибо». Приёмник попадает в сборку с `PUBLISH=1` или `LEADS=1`.

## Что в Telegram и таблице

По умолчанию (`full => false`) туда не уходят полный номер и сведения о здоровье: номер с маской `+7 9** ***-12-34`, полные данные по кнопке в amoCRM. Серверы Telegram и Google за границей; с `full => true` клинике нужно уведомление Роскомнадзора о трансграничной передаче и строка в политике.

## Установка на хостинг (Jino, Beget, Timeweb и т. п. с Apache и PHP 8.1+)

Сейчас (22.10.2026) у клиники в Джино только домены (smartmed.clinic до 20.07.2027, ummed.ru) и почта на домене, хостинга нет: нужен контейнер с PHP и SSH. Домен smartmed.clinic смотрит на заглушку Tilda (185.215.4.58), SSL Let's Encrypt есть. Письма лучше слать через SMTP smtp.jino.ru с ящика info@smartmed.clinic; у домена нет SPF-записи, без неё письма могут попадать в спам.

В amoCRM (сверено 22.10.2026): воронка «Колл центр» 7066886, этап «ВХОДЯЩИЙ ЗВОНОК/ЗАЯВКА» 59222266 (туда же ставят сделки Tilda и Calltouch), ответственный по умолчанию 9946386, UTM, REFERRER, YCLID, GCLID, _YM_UID и ROISTAT пишутся в поля «Статистика» по кодам.

1. Собрать сайт: `PUBLISH=1 SITE_URL=https://домен npm run build`, залить `dist/` в корень сайта (вместе с `.htaccess` и `lead.php`).
2. Рядом с корнем сайта или уровнем выше (у Джино `~/umed-leads`, корень сайта `~/domains/<домен>`), **не внутри корня**, создать папку `umed-leads` и положить туда `config.php` из `server/config.sample.php` с настоящими ключами. Если хостинг не даёт папку выше корня, путь задаётся переменной `UMED_LEADS_CONFIG`.
3. Ключи в `config.php`:
   - `cron_key`, `file_key`: случайные строки (`openssl rand -hex 24`);
   - `amo.token`: долгосрочный токен своей интеграции amoCRM (Настройки → Интеграции → Создать интеграцию → Ключи и доступы), права «Сделки, контакты, примечания»;
   - `amo.status_id`, `amo.responsible_user_id`: этап и ответственный, если не первый этап и не владелец токена;
   - `telegram.token` от @BotFather, `telegram.chat_id` группы администраторов (бота добавить в группу);
   - `sheets.url` и `sheets.secret`: веб-приложение из `server/google-sheets.gs` (инструкция в начале файла);
   - `mail.to` и `mail.from`, если клиника хочет письма: отправитель — ящик на домене сайта, иначе письма уйдут в спам.
4. Крон хостинга раз в 5 минут: `curl -s "https://домен/lead.php?cron=<cron_key>"` (или `wget -qO- …`).
5. Проверить: отправить заявку с сайта, увидеть сделку, сообщение и строку; выключить токен amoCRM на минуту и убедиться, что пришла тревога, а после возврата сделка создалась повтором.

`config.php` и папку `umed-leads` в репозиторий не коммитить.
